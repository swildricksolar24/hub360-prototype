## Interpretation

This is the first run, so there is no change to compare against. Two of the four checks could not run the way they were designed. The app imports Volt by relative path ("../../components/Button/Button"), not from a package name or path alias. So adoption reads 0% even though the app uses Volt everywhere, and API fidelity (invented components or props) was not measured. Treat both as "not measured", not as a pass or a fail.

The 147 findings that were measured are all "review", with no fails:
- Raw dimensions (102): almost all are layout sizes in the Inventory CSS modules (widths, heights, grid columns, 44px control heights, 1px visually-hidden labels). Volt has spacing, radius and stroke tokens but no size tokens, and most of these lines already carry a comment saying so. items.module.css alone has 31. Colors are clean: no raw hex values were found.
- Accessibility (45): mostly noise. The 23 autoFocus findings are each modal's first field, on purpose. Most "no accessible name" hits are hidden submit buttons, hidden file inputs and a hidden autofill select. The 6 "click without a keyboard handler" hits are the clickable radio cards and inbox rows, worth a quick look.

Fixes to do first:
- Add a path alias such as "@volt" for src/components (tsconfig and Vite) plus a barrel file. Then set componentsPkg to it, so adoption and API fidelity can be measured.
- Decide whether repeated layout sizes (44px, 320px, 280px) should become tokens in Figma. If not, leave them; the comments explain them.
- Check the 6 click-handler cards for keyboard access.

## How this was measured

Static checks only, no model calls: imports, API fidelity (components and props against the real exports of the design system package), token discipline (hardcoded colors and sizes) and static accessibility. Checks are adapted from [open-design-system-bench](https://github.com/christophhdesign/open-design-system-bench) (MIT). A dimension that could not be measured shows n/a and is left out of the score, never counted as a pass.

What it does not check: documentation, design rules or guidelines, Figma, Storybook, hand-built components that imitate a design system one (a custom button built from a `div`), or duplicate components. It compares code against the design system package's component list and the token values, nothing more.
